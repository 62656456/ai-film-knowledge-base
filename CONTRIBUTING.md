# Contributing

This repository accepts corrections, stronger sources, original theory or practice notes, public review standards, rights-cleared original diagrams, and translations.

## Choose the public route

1. Use `knowledge/A-理论层/` for a durable mechanism or creative judgment that remains useful without one platform.
2. Use `knowledge/B-实战层/` for a reusable workflow, output contract, prompt method, or bounded platform practice.
3. Use `knowledge/C-审核与验收层/` for status, evidence, scope control, review, directed return, pass criteria, and public-entry gates.
4. Use `knowledge/00-总纲/` only for public navigation, structure, policy, or errata.

The public C route must never be used to restore the private AI-infrastructure, retrospective/validation, or inspiration layers.

## Write for direct GitHub reading

5. Keep every note independently understandable; do not require a private repository, personal project, local application, or companion Skill.
6. Procedural notes must state purpose, inputs, workflow, output, return conditions, pass criteria, and current evidence status.
7. Use normal Markdown links with repository-local targets that exist. Do not add Obsidian wikilinks or embeds.
8. Do not leave image-withheld placeholders, local absolute paths, conversation IDs, personal project details, or private evidence in a contribution.
9. Distinguish stable mechanisms, source-backed interpretation, practical experience, candidate methods, time-sensitive facts, and unknowns.
10. Cite primary or authoritative sources for changing product, platform, policy, price, model, or technical claims.

## Review and return

11. A validator pass proves repository structure, not creative acceptance. Keep candidate, in-review, changes-requested, approved, and published states separate.
12. When requesting changes, name the failed gate, observed evidence, earliest broken decision, minimum correction, protected passing items, and resubmission proof. Do not use a vague “improve it” return.
13. Do not paste full third-party courses, articles, books, scripts, transcripts, or private chats.

## Images

14. Do not add an image unless its author or source, license or explicit permission, attribution, modification history, knowledge purpose, embed location, and privacy review are documented.
15. Current public knowledge illustrations must be original SVGs under `docs/assets/knowledge/`, registered in `docs/VISUAL_ASSETS.md`, referenced from Markdown, and embedded with the exact descriptive alternative text.
16. Do not copy, trace, or transform any of the 730 withheld source-vault images. The 622 conditional candidates remain private until the missing unified authorization is explicit; 86 have insufficient evidence and 22 are excluded.
17. Preserve the Simplified Chinese source note when contributing a translation.

## Validate

Run:

```text
python scripts/validate_repository.py
```

The validator regenerates `CATALOG.md`; include the deterministic catalog change when adding or renaming a note. A pull request must leave no generated catalog diff after validation.
