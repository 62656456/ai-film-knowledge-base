# 提示词体系选型裁决

> 用途（裁决卡）：在图片提示词、连续视频、逐镜调用包与平台待定方案之间选入口。2026-07-30 更新；视频不再服从固定“十段式/六大模块”，先由当前 `ai-storyboard-director` Skill 判断平台与执行模式。

## 裁决表

| 我在做什么 | 当前入口 |
|---|---|
| 英文图片提示词 | B2-01 七字段，结合目标图片模型调整 |
| 即梦 / Seedream 中文图片 | B3 对应平台图片规则 |
| 视频分镜设计 | `ai-storyboard-director` 的人读五列表 |
| 单镜头视频生产 | `ai-storyboard-director` 的 `LONG_TAKE` 门 |
| 多机位、反打、持物、精确对白视频 | `ai-storyboard-director` 的 `SHOT_PACKAGE` 门 |
| 平台或模型版本未知的视频 | `ai-storyboard-director` 的 `PLATFORM_PENDING` 门 |
| 已有废片的修复 | 先审实际帧，再只修失败环节 |

## 视频规则优先级

`用户当前明确要求 > 用户已确认的剪辑镜头与剧情 > 目标平台已验证硬限制 > 当前 ai-storyboard-director Skill > 其他知识卡`

其他卡片只供应术语、光线、色彩和平台已验证能力，不得改写视频执行模式或强制用户可见格式。

## 三条裁决原则

1. **图片与视频分流**：图片字段不能直接套成视频生产合同。
2. **先平台、后格式**：先确认平台、版本、素材槽、首尾帧、音频和时长能力，再编译每次模型调用包。
3. **生成架构优先**：多次切镜、跨镜状态和精确对白不再塞入一条长提示词；切镜交给剪辑，状态交给首尾帧和逐镜调用包。

## 退役

2026-07-30 起，B2-19 的十段式信息 10/10、V3.0 六大模块、短视频内自动多次切镜不再是强制标准。其问题不是字段不全，而是把模型无法稳定执行的跨切记忆误当成文字可以保证的能力。

写完视频内容后的判断不再是“字段是否齐全”，而是：

- 目标平台是否已确认；
- 生成模式是否选对；
- 每次模型调用是否独立可执行；
- 对白是否按真实语速与音频波形容纳；
- 实际视频是否通过人物、空间、道具、光线和环境验收。
