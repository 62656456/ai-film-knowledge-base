# Skill模块审核与独立使用标准

> 用途（模块门）：判断一个 Agent Skill 是否能在 GitHub 被读懂、能被单独拿走、能在失败时正确退回，并且不会用结构通过冒充实战通过。

## 八段公开合同

每个独立 Skill 的 GitHub 说明至少回答：

1. **用途**：解决哪个可见问题；
2. **设计理念**：为什么按这个因果顺序工作；
3. **输入**：必须已知、已批准或由用户提供的内容；
4. **流程**：从输入到可用输出的步骤；
5. **退回设计**：每类失败退到哪一层；
6. **审核门**：交付前逐项检查什么；
7. **过关标准**：什么可观察证据足够；
8. **输出与边界**：交付什么，明确不决定什么。

## 独立使用门

- [ ] 根目录存在标准 `SKILL.md`
- [ ] 运行所需引用、脚本、模板和资产都在该 Skill 文件夹内
- [ ] 不依赖维护者本机路径、私人知识库或另一个未声明仓库
- [ ] 可选平台元数据不是运行硬依赖
- [ ] 单独下载后仍能找到全部相对链接
- [ ] GitHub 页面直接链接到 `SKILL.md`，不要求先安装才能理解
- [ ] 未安装原生 Skill 的 Agent 仍可把 `SKILL.md` 与本地资源作为指令阅读

## 设计与流程门

- 一个主 Skill 对当前交付物负责；第二个 Skill 只有在输出合同不同且确有必要时接手。
- 任务顺序由因果关系决定，不因目录顺序或“流程完整”增加无关步骤。
- 上游决定通过后形成明确交接物；下游不得静默改写。
- 失败退回责任层，不从头重跑整条链。
- 需要人类审美、付费、发布、删除或正式入库的动作必须保留权限门。

## 审核与过关门

| 检查层 | 通过标准 |
|---|---|
| 结构 | frontmatter、文件、依赖和链接正确 |
| 可读 | GitHub 说明能让首次访问者知道用途、流程、退回和证据 |
| 可装 | 支持的 Agent 能发现或接收完整文件夹 |
| 可用 | 输出是用户可直接判断或继续生产的产物 |
| 实战 | 真实任务记录了触发、产物、修改与反馈 |
| 接受 | 用户明确认可；不能由作者自检代替 |

## 版本与状态

- **Packaged**：结构上可发布。
- **Deployed**：当前运行环境已使用，不等于长期稳定。
- **Experimental**：隔离、默认不安装、未获正式批准。
- **Practice-validated**：至少三个不同真实任务留下被接受的证据。
- **Retired**：有明确停止理由，不得从历史文件自动恢复。

## 失败时怎样退回

| 失败 | 退回 |
|---|---|
| 单独包缺依赖 | 包装与相对引用 |
| 能加载但输出空泛 | 设计理念、输入或输出合同 |
| 检查项很多但结果不可用 | 最早影响可用性的内容决定 |
| 一个 Skill 越权改写另一个层 | 交接合同与责任边界 |
| 自动验证通过但真实任务失败 | 实战样本、失败原因与门禁修订 |
| 公开说明与运行正文不一致 | 同步修改两者并重新验证 |

通过本卡只说明对应层级。结构验证不得被写成“所有 Agent 原生兼容”或“已稳定产出高质量结果”。
