# 输入冻结与范围守恒

> 用途（开工门）：在制作、修改或发布前，锁定最新要求、完整范围、禁止项与最低证据，防止旧项目、旧版本和旁支优化混入当前结果。

## 四项冻结卡

| 字段 | 必须写清 |
|---|---|
| 点名结果 | 最后要让人直接获得什么 |
| 当前来源 | 哪些正文、资产、链接、决定或版本是真实输入 |
| 本次禁止 | 哪些内容已否定、停止、退役、无权公开或不可改变 |
| 最低证据 | 什么真实结果才能证明本轮完成 |

简单任务可以在内部保持这四项；复杂、批量、发布或跨模块任务应留下可复核记录。

## 最新指令覆盖旧计划

一旦目标、范围、对象、媒介或停止项改变：

1. 立刻停止与新要求冲突的生成、写入和发布；
2. 撤销冲突结论，不用“之后再补”维持旧计划；
3. 更新冻结卡；
4. 重新核对还可保留的已完成结果；
5. 从最早受影响的步骤继续。

## 扩大范围前的三项比较

每次准备增加模块、工具、依赖、文件、精度或步骤时，比较：

- 原始目标是什么；
- 当前动作怎样提高点名结果的通过率；
- 是否存在更小、可逆、同样有效的替代。

若当前动作不提高验收通过率，或新增问题多于解决的问题，把它记为候选，不进入本轮正式范围。

## 全部覆盖的最低写法

当任务出现“全部、所有、完整”时，必须同时交代：

- 冻结时间与来源范围；
- 逐项清单或可复核索引；
- 去重和清洗规则；
- 无法覆盖的边界；
- 抽样与全量的区别。

关键词扫描只能生成复核候选，不能单独证明完整覆盖。

## 通过标准

- [ ] 最新要求没有被旧计划覆盖
- [ ] 点名结果与交付媒介一致
- [ ] 禁止项能在产物中被实际检查
- [ ] 范围扩张有直接验收收益
- [ ] “全部”有清单、规则和边界
- [ ] 最低证据与交付物类型匹配
